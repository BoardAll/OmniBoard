## 1. 目标与范围

### 1.1 本稿目标

1. 确定实时链路的技术栈与客户端库落层（Socket.IO over WebSocket；桌面 sioxx / Web 官方 JS 客户端，零协议自研）。
2. 把「互动白板」拆成可实现的主要交互流程：加入房间、首同步、实时操作广播、笔迹、橡皮擦与冲突解决、光标感知、编辑锁、跟随/演示、断线重连。
3. 给出与现有代码（C++ `sync`/`crdt` 域、FFI、Dart 画布与骨架、服务端）的明确接线点。

### 1.2 本稿不包含（保持预留）

- 音视频 / 屏幕共享（仍走 mediasoup 预留，M10.2）
- 录制 / 回放实现（M10.4，仅对接点）
- 投票 / 计时 / 分组讨论的完整业务（M10.5，仅留事件名）
- 真实持久化存储（沿用服务端内存仓库现状）

### 1.3 落层与端优先级（重要设计输入）

**端优先级**：

- **Web 端（浏览器）为第一优先端**：选择 WebSocket / Socket.IO 生态的核心动机就是浏览器原生支持——官方 JS 客户端零安装接入，无需任何本地组件。
- **Web 端分期**：W1 协作层先行（在线成员 / 远端光标 / 举手 / 跟随等元数据互动，不依赖画布引擎）；W2 待 WASM 核心就绪后开画布元素级 op 同步。

**落层（本方案核心决策，见 §2.2/§2.4）**：

| 端 | 落层 | 理由 |
|---|---|---|
| 桌面 | **C++ 引擎层**：`core/src/sync/`（把 `providers.h` 的 `reserved::Transport` + `TransferType::SocketIO` 占位变真） | ①架构已预留该位置，不新增架构概念；②网络与 crdt/离线队列/版本水位同侧，远端 op 进程内直接 `applyRemote`；③桌面无跨平台统一包袱（sioxx+Boost.Asio 在桌面三 OS 成熟） |
| Web | **应用层**：`apps/web/lib/services/`（浏览器 WebSocket + 官方 JS 客户端） | 浏览器无法运行 C++ 引擎（WASM 核心仍为占位）；协作层可不等 WASM 直接做 |
| 平台层 `platform/*` | **不放** | 定位是系统能力插件（窗口/快捷键/托盘/WASM 加载器）；网络不是系统能力，放这里要每平台各实现一遍协议并吃 MethodChannel 双重序列化 |

**桌面现状提醒（落地必读）**：画布 / 元素模型目前在 Dart 侧自实现，协同落地需要两条管道——

1. **出口**：Dart 画布操作 → 生成 CRDT op → `crdt.applyLocal`（FFI）→ 出站；
2. **下发**：引擎事件（经 §8.2 的 `sync.events`）→ Dart 应用到画布 → 重绘。

**协同状态权威在 C++ crdt 域**，Dart 画布为其投影；本节两条管道是"现状画布"与"目标协同"的桥。

## 2. 技术选型

### 2.1 为什么是 Socket.IO

**第一动机：Web 端优先**——WebSocket 是浏览器原生能力，Socket.IO 官方 JS 客户端零安装接入；桌面端用 C++ 库（sioxx）对接同一协议与消息契约，不需要为浏览器另造通道。

| 能力 | 说明 | 对本项目价值 |
|---|---|---|
| 房间（room）模型 | 服务端原生 `socket.join(room)` + `to(room).emit()`；同连接多房间广播自动去重 | `board:<boardId>` 广播隔离 |
| **单播** | 每个连接的 `socket.id` 本身就是一个专属房间：`io.to(socketId)` / `socket.emit`；跨会话定向用自定义房间 `user:<userId>`；**ack 回调即定向回执** | `joined`/lock 回执/`room:error`/`fetchOps` 响应等点对点场景 |
| ACK 回执 | `emit(ev, data, ack)` | 每条操作可拿到服务端处理结果，替代自研确认 |
| volatile 消息 | 不可写时直接丢弃 | 光标/预览/笔迹点流等高频易丢消息的降载通道 |
| 自动重连 + 连接状态事件 | 客户端 SDK 内置（指数退避） | 重连状态机有标准语义可对齐 |
| 多传输降级 | WebSocket / HTTP long-polling | 弱网保底（**仅 Web 端保留该选项**；桌面直连 WS） |
| 二进制支持 | `BINARY_EVENT` 包 | CRDT `encodeUpdate` 二进制路径备用 |
| 水平扩展 | `@socket.io/redis-adapter` | 多实例房间扇出（预留） |

> 对照结论：裸 WS 自建"房间 + 可靠性配套"（心跳防半开连接、ack/重试、重连后 rejoin、慢客户端背压、多端信封）≈ 500~1500 行自研，且违背「零协议自研」原则——不采用。

### 2.2 客户端库选型（定稿）

| 端 | 库 | 协议版本 | 落点 | 选择理由 |
|---|---|---|---|---|
| **桌面（三 OS）** | **sioxx** 0.3.0（C++17，Boost.Asio/Beast + nlohmann/json） | Engine.IO v4（= Socket.IO v3/v4） | `core/src/sync/socketio_transport.{h,cpp}` | 网络与 crdt/离线队列同侧；EIO v4 标准适配 socket.io@4；依赖在桌面三 OS 成熟；换库通过薄封装隔离 |
| **Web（浏览器）** | **官方 socket.io JS 客户端** | Socket.IO v5（EIO v4） | `apps/web/lib/services/`（`dart:js_interop` 桥） | 浏览器原生 WebSocket；官方实现特性最全（volatile、自动重连、连接状态恢复） |
| 不采用 | `socket.io-client-cpp` | EIO v3（Socket.IO v2） | — | 协议旧（服务端需 `allowEIO3: true`），库停滞 |
| 不采用 | `libwebsockets` + 自定义信封 | —（仅 WS 传输层） | — | 只做 WS/WSS、不做 Socket.IO 协议；「libwebsockets + 自己补分帧」≈ 自研 |
| 不采用 | Dart `socket_io_client`（双端统一备选） | Socket.IO v5 | — | 桌面网络下沉 C++ 后不再需要"双端统一"；Web 端改用官方 JS 客户端 |

**sioxx 已知缺项（由其 roadmap 未实现，均由应用层补齐）**：

| 缺项 | 应用层兜底 |
|---|---|
| volatile 发送（可丢语义） | **迟滞队列**：每类预览消息仅保留最新一帧（队列深度 1，旧帧覆盖丢弃） |
| ack 自动重试 | **重试队列**：3s 超时 × 3 次，仍失败转离线队列（§5.4） |
| 断线期间漏包恢复 | **水位差分**：`lastSeenVersion` + `fetchOps` 补洞（§5.12） |

### 2.3 Socket.IO 协议栈细节（库内部实现，保留用于联调排障）

```text
┌─────────────────────────────────────────────┐
│ Socket.IO 事件层（v5 包类型）                │
│  0 CONNECT / 1 DISCONNECT / 2 EVENT /        │
│  3 ACK / 4 CONNECT_ERROR / 5 BINARY_EVENT /  │
│  6 BINARY_ACK                                │
├─────────────────────────────────────────────┤
│ Engine.IO v4 分帧                            │
│  0 OPEN / 1 CLOSE / 2 PING / 3 PONG /        │
│  4 MESSAGE / 5 UPGRADE / 6 NOOP              │
├─────────────────────────────────────────────┤
│ WebSocket（桌面：sioxx/Boost.Beast；Web：浏览器原生） │
├─────────────────────────────────────────────┤
│ TLS / TCP                                    │
└─────────────────────────────────────────────┘
```

关键帧样例（服务端为 socket.io v4.x，协议即 Socket.IO v5 / Engine.IO v4）：

| 方向 | 原始帧 | 含义 |
|---|---|---|
| S→C | `0{"sid":"...","pingInterval":25000,"pingTimeout":20000}` | Engine.IO OPEN（握手响应） |
| C→S | `40/board,{"token":"<jwt>","boardId":"..."}` | 连接 `/board` 命名空间（auth 载荷） |
| S→C | `40/board,{"sid":"..."}` | 连接成功 |
| S→C | `44/board,{"message":"Unauthorized"}` | 连接拒绝（token 无效/无权限） |
| C→S | `42/board,["board:ops",{...}]` | 发送事件 |
| C→S | `421/board,["board:ops",{...}]` | 发送事件并要求 ack id=1 |
| S→C | `431/board,[{"ok":true}]` | ack 回执 |
| S→C | `2` / C→S `3` | Engine.IO v4 心跳（**服务端发起 ping，客户端回 pong**） |

连接方式：**默认直连 WebSocket**（`wss://host/socket.io/?EIO=4&transport=websocket`）——桌面（sioxx）强制 websocket transport；Web 端默认直连 WS，**保留 polling 降级选项**作为弱网保底。`pingInterval=25s / pingTimeout=20s` 由服务端 OPEN 帧下发，由库按帧内数值执行。

### 2.4 sioxx 跨平台边界（落层依据）

| 平台 | sioxx 可用 | 说明 |
|---|---|---|
| Windows / macOS / Linux | ✅ | Boost.Asio 分别用 IOCP / kqueue / epoll |
| Android / iOS | ⚠️ 理论可行 | Boost.Asio 可编译；项目移动端未规划 |
| **浏览器（WASM）** | ❌ | Boost.Asio 依赖操作系统 socket，浏览器沙箱无 POSIX socket；Emscripten 仅有专用 `emscripten_websocket` API——**C++ 网络栈无法覆盖 Web** |

结论：**"桌面跨三端、浏览器不跨"与分端落层设计完全吻合**——桌面一份 C++ 实现，Web 用浏览器原生通道；若未来要求"Web 也走 C++ 网络栈"，此路不通（需换 Dart/JS 方案），当前设计已规避该风险。

### 2.5 ❓决策点 D2：载荷格式

- **v1.0 默认 JSON**（与全仓 FFI 边界「UTF-8 JSON」一致，可读、可测、易调试）。
- Socket.IO v5 协议原生支持二进制附件：当单帧 > 256KB 或压测显示 JSON 编解码成为瓶颈时，可评估二进制事件（或经 POC 验证 MessagePack 类编码），客户端/服务端同步切换 parser，无需改消息契约。

## 5. 主要交互逻辑（核心章节）

### 5.1 角色与房间模型

- 房间粒度：**一个白板一个房间** `board:<boardId>`；子频道（按页）暂不做，页面过滤在客户端完成，为分组讨论（M10.5）预留 `board:<id>:group:<gid>`。
- 角色沿用《预留接口设计》`InteractiveRole`：`Host / CoHost / Presenter / Participant / Viewer / Guest`。
- 与既有权限域的映射（`wb::permission` 级别 Read < Write < Share < Admin）：

| 房间角色 | 引擎权限级别 | 可发操作 | 说明 |
|---|---|---|---|
| Host / CoHost | Admin | 全部 | 房间管理（踢人/授权/模式切换）；恒可写 |
| Presenter | Write | 绘图/编辑/翻页 | free 模式默认可写（≥Write，2026-11 修订）；present 模式仅 Presenter（+恒可写角色）可写 |
| Participant | Write（free）/ Read（present，授权后 Write） | free：绘图/编辑；present：授权后 | free 模式默认可写（2026-11 修订）；present 模式收窄为只读，经 CoHost 及以上授权（`interactive:grantControl`）后临时可写 |
| Viewer | Read | 仅光标/举手 | 跟随/演示模式的默认角色；free/present 一致只读 |
| Guest | Read（默认） | 仅光标/举手 | 免登录分享链接；free/present 均默认只读（2026-11 修订确认；可被显式授权） |

### 5.2 连接与握手（时序）

```text
桌面：C++ SocketIOTransport(sioxx) / Web：JS 客户端      Socket.IO Server
      │ 1. ws connect /socket.io/?EIO=4&transport=websocket        （桌面强制；Web 默认，可留 polling 降级）
      │──────────────────────────────────────────────▶
      │ 2. ◀──── 0{"sid","pingInterval":25000,"pingTimeout":20000}
      │ 3. 40/board,{"token","boardId","clientVersion"}
      │──────────────────────────────────────────────▶
      │ 4a. ◀──── 40/board,{"sid"}      连接成功（引擎 TransportState=Connected；UI 映射 WbSyncStatus=online）
      │ 4b. ◀──── 44/board,{"message"}  拒绝（token 过期/无权限/版本不兼容）
      │        → Failed（UI 显示 error），本地继续单机编辑（离线队列保留）
      │ 5. 心跳：S→C `2` → C→S `3`（按 OPEN 帧参数）
      │ 6. 重连（连接断开时）：指数退避 1s→2s→4s→…→30s（±20% 抖动），成功后回到步骤 1
```

- 握手 auth 载荷 = 13 svc-api 签发的 JWT + boardId；匿名分享场景由服务端换发 room-scoped token（Guest）。
- `clientVersion`（如 `1.0.0`，取根 `VERSION`）用于服务端拒绝不兼容客户端。
- 状态映射：引擎 `TransportState`（Inactive/Connecting/Connected/Reconnecting/Failed）→ Dart `WbSyncStatus`（offline/connecting/online/syncing/error）。

### 5.3 加入房间与首同步（状态收敛）

```text
客户端                                服务端                              其他参与者
  │ board:join {boardId, pageId} ────▶ │
  │                                    │ 校验 token/角色（复用 13 的 board 协作者）
  │                                    │ 记录参与者；分配 sessionId
  │ ◀── board:joined {                 │
  │      participants[], 角色, 模式,    │
  │      locks[],                       │
  │      stateVector,                  │ ← 版本水位（每 actor 最大 seq）
  │      snapshot（可选，见要点 3）      │
  │    }                               │
  │ crdt.merge(localState, snapshot) → 本地重放未确认的 pending op
  │ ──── board:joinAck {lastLocalSeqs} ▶ │
  │ ◀── board:ops (补发缺失增量) ──────── │
  │ ◀── presence:* 全量快照 ──────────── │
  │                                    │ ──── board:participants {joined} ▶
```

要点：
1. **首同步产物直接喂给既有 CRDT 域**：`snapshot` 走 `crdt.parseEncodedState`/`merge`；增量走 `applyRemote`。引擎侧不新增合并逻辑。
2. 本地离线期间产生的 pending op 在首同步后重放（CRDT 的 LWW + (actor,seq) 去重保证幂等）。
3. **快照策略（服务端不做 CRDT 合并的直接推论，详见 §7）**：MVP 不裁剪——房间生命周期内 op 日志全量保留，新成员 join 即全量回放增量；长会话（水位超阈值）再由"水位最高的客户端"上传 checkpoint（M3+）。

### 5.4 实时操作广播链路（核心）

**发送侧（本地用户操作，桌面走引擎）**

```text
用户操作 → 命令层（撤销栈）→ crdt.applyLocal(op)        // op = {actor,seq,key,value,timestamp,origin}
        → sync.sendOperation(op)                        // FFI 调用
             ├─ 在线：sync 域出站队列 → 100ms 攒批 → emit(board:ops, [op…], ack)
             │         ack 超时 3s → 重发（最多 3 次）→ 仍失败视为断线，转离线队列
             └─ 离线：sync 域 pending 队列（既有语义转真），重连后随差分一起 flush
        → 本地立即渲染（乐观应用，不等待服务端）
```

**服务端**

```text
board:ops 到达 →
  1) 写权校验：effectiveCanWrite（§5.1 / §5.10）——free 模式：角色 ≥ Write；present 模式：仅 Presenter；grantedWrite 与 Host/CoHost 恒放行
  2) 去重：(actor, seq) 已见过 → 直接 ack {ok:true, dup:true}
  3) 校验 seq 连续性：gap → ack {ok:false, missingSeqs:[…]}（发送方补发）
  4) 追加 op 日志（版本水位推进）
  5) 广播 to(room).emit('board:ops', [op…], {from: actor})（默认排除发送者 socket）
  6) 审计采样（每条 op 落审计太重：默认按会话+操作类型聚合，❓D4）
```

**接收侧（远端操作，合并发生在引擎内）**

```text
sync 域入站队列 → 引擎内直接 crdt.applyRemote(op[])     // 与网络同侧，不走 FFI
  ├─ (actor,seq) 去重（幂等，重复到达直接丢）
  ├─ LWW 合并 + actor tie-break（既有语义；ApplyRegister 返回"是否生效"）
  └─ 生效的 op 进"事件下发队列"（§8.2）→ Dart drain → 应用到画布 → 脏区重绘

丢包自愈：入站发现某 actor 的 seq 跳号 → emit(board:fetchOps, {actor, fromSeq}) → 服务端补发
```

**增量数据的分工（谁去同步）**：

| 场景 | 谁发起 | 增量从哪来 | 传递 | 谁应用 |
|---|---|---|---|---|
| 日常 op | 操作者客户端（push） | 本地生成 | 房间广播 | 其他所有端 |
| 丢包补洞 | 落后方客户端（pull） | 服务端 op 日志裁差分 | 单播回请求者 | 请求者 |
| 断线重连 | 落后方客户端（pull） | 服务端 op 日志（按 `lastSeenVersion`） | 单播 | 请求者 |
| 新成员首同步 | 服务端（响应 join，push） | 服务端日志 + 可选快照 | 单播 | 新成员 |
| 离线队列冲刷 | 操作者客户端（push，重连成功后） | 自己断线期间攒的 op | 可靠上行 | 服务端（去重后广播给他人） |

> 服务端只记流水账（去重/水位/裁差分/转发），**不做 CRDT 合并**——合并语义唯一权威在客户端引擎，避免 Node 侧出现第二套语义。

**高频中间态优化（关键交互体验）**

| 操作类型 | 中间态（拖拽/画笔移动/擦除划过） | 终态（松手/落笔/提交） |
|---|---|---|
| 通道 | `presence:preview`（**volatile**，可丢；载荷带 `kind`：`transform` / `ink`） | `board:ops`（可靠 + ack） |
| 频率 | 33ms（约 30Hz）本地节流 | 每次提交 1 条（或攒批） |
| 载荷 | 元素 id + 目标变换（transform）/ `strokeId` + 增量点（ink） | 完整 CRDT op |
| 远端行为 | 临时鬼影（不写状态、不入撤销栈） | applyRemote 落定 |

> 收益：拖动/笔迹过程丢 1~2 帧无感；终态永不丢。
>
> ⚠ sioxx 无 volatile 发送（roadmap）→ 桌面由**应用层迟滞队列**模拟（每类消息仅保留最新一帧，队列深度 1）；Web 官方 JS 客户端原生支持 volatile 直接启用。

### 5.5 笔迹同步（两阶段模型）

自由笔迹（`drawing` 元素，`points` 世界坐标）是最高频的同步对象：采样率高、但中间过程**不需要可靠性**。方案：绘制中走"可丢预览流"，抬笔后走"可靠终态"，远端用鬼影过渡。

```text
绘制者(本地)                      服务端                          其他参与者(同页)
 PointerMove 采样（本地即时渲染,0 延迟）
   │ 每 33ms 增量点
   ├─ presence:preview(kind:ink) ─▶ volatile 广播 ─────────────▶ 鬼影笔画缓冲
   │   {strokeId, seq, Δpoints,      (可丢,不补发)              (只画,不落模型/不入 CRDT/不入撤销栈)
   │    style}
   │   (丢帧无妨;缺口段连线兜底)
  抬笔
   ├─ 本地简化（Douglas-Peucker 抽稀,亚像素公差）
   ├─ crdt.applyLocal(op)     key=elementId, value=drawing 元素（终态一条 op）
   ├─ board:ops [op] ─────────────▶ 去重/水位/落日志
   │   (ack 重试 3s×3,            ├─ 广播 ─▶ 按 elementId 移除鬼影
   │    离线进队列)                │          applyRemote → 落模型重绘
   └─ ack 确认
```

**边界处理**：

| 边界 | 处理 |
|---|---|
| `strokeId` 全局唯一 | `{actor}-{localSeq}`（与 crdt actor/seq 命名对齐）；远端按 id 匹配鬼影与终态 |
| 乱序：终态先到、预览后到 | 记录"该 strokeId 已终态"，后续预览直接丢弃 |
| 预览丢帧缺口 | 空缺段直接连线兜底；终态替换后无痕 |
| 绘制者中途断线 | 鬼影缓冲 TTL 5s 淡出移除；终态在离线队列中，重连后仍会到达 |
| 撤销 | 绘制中不入撤销栈；抬笔后一次入栈；undo = 删除该元素一条 op |
| 多人同画 | 每支笔独立 strokeId 并存；预览流**只广播给同页用户**；房间级活跃笔频控（超限降采样） |
| 数据量 | 50ms 增量点 ≈ 0.3KB/帧 ≈ 6KB/s/支笔；同曲线走"每点一 op" ≈ 60KB + 300 次 ack（差 30 倍以上） |

> **前置项**：`drawing` 类型尚未进入 core 元素契约（`canvas_model.dart` 已记录该偏差）——笔迹终态落 CRDT 前需补（05-core-model 评估项，见 §4）。

### 5.6 编辑锁与冲突处理（软锁 + 锁粒度）

- **软锁语义**（体验层）：元素开始编辑（双击文本/拖动专业元素/打开编辑器）→ `lock:acquire {elementId}`：
  - 空闲 → 授予，广播 `lock:changed`；他人画布上该元素显示「XX 编辑中」并禁止操作入口（仍可查看）。
  - 已被占用 → 拒绝并返回占用者（**单播回执**）；本端提示（不做只读预览，M2 决策 D2-C）。
- **锁粒度按元素类型**（与 §5.8 冲突矩阵对应）：

| 编辑对象 | 锁粒度 |
|---|---|
| 文字 / 通用元素 | 元素级 |
| 表格内容 | 单元格级（MVP 可整表）；**行列结构操作整表锁** |
| 流程图/导图 | MVP 整元素锁（全窗编辑器打开即锁）；节点级为演进方向 |
| 2D/3D 变换 | 拖动走预览流（不锁）；尺寸调整对话框期间元素锁 |

- **锁生命周期**：TTL 30s，持有者每 10s 心跳续约（`lock:renew`）；掉线/超时自动释放并广播。
- **与橡皮擦联动**：橡皮擦划过"被他人锁定/编辑中"的元素时**跳过**（本地基于 `lock:changed` 状态判断），不产生删除 op。
- **兜底**：锁只防冲突不防覆盖坏；所有落定仍走 CRDT（LWW + tie-break），即使锁失效（如网络分区）状态最终一致、不崩坏。
- 锁定状态**不进入 CRDT 状态**（属会话态），仅存服务端内存 + `board:joined` 下发；断线重连后重新建立。

### 5.7 删除与橡皮擦同步

**远端表现**：橡皮擦是**离散事件**（划过元素→删）——每划过一批元素立即攒批（100ms）发删除 op（不等抬笔），远端元素消失（本地加 150ms 淡出动画平滑，纯表现层）。橡皮擦光标/路径预览（volatile）为 M2+ 可选增强。

**删除语义（exists 规则）」**：元素存在性用独立 key `el:{id}:exists`；**普通修改操作不改变存在性**。

| 场景 | 规则 | 结果 |
|---|---|---|
| A 擦 X vs B 拖 X | B 的 transform op 照常记录，渲染以 `exists=false` 为准 | 元素删除；B 的拖动"不白做"——undo 复活后位置即 B 拖到的位置 |
| A 擦 X vs B 也擦 X | 删除幂等（同 key 写 false） | 无冲突 |
| A 擦 X vs B 复制 X | 副本新 id 新增 | 副本存活，无冲突 |
| A 擦 X vs B 正在编辑 X | 橡皮擦跳过锁定元素；极端并发下 B 提交时元素已不存在 → 提交降级 no-op 并提示 | 不产生"编辑幽灵元素" |
| A 擦 X vs B 删 Y | 不同 key | 天然并行 |

### 5.8 各元素类型并发冲突矩阵

**铁律：key 的粒度 = 冲突合并的粒度**（crdt 域状态即"按 key 的 LWW register map"：同 key 比时间戳，并列时 actor 字典序大者胜，见 `crdt.cpp::ShouldApply`）。三层防线：软锁（挡高频编辑）→ key 粒度（缩并发窗口）→ LWW 兜底（最坏"一方白改"，永不数据损坏）。

| 元素 | 操作 | key 粒度 | 并发行为 | 抑制手段 |
|---|---|---|---|---|
| 通用 | 位置/尺寸/颜色/z 序 | `el:{id}:{field}` 字段级 | A 改色 + B 移动 = 都保留；同字段才 LWW | 拖动过程走 volatile 预览流，落定才写 op |
| 文字 | 文本内容 | `el:{id}:text` 整体 | 后提交整体覆盖（**不做字符级**） | 编辑期元素软锁（"XX 编辑中"） |
| 表格 | 单元格内容 | 单元格级（以单元格 id） | 编辑不同格 = 完美合并 | 单元格软锁 |
| 表格 | 增删行列（结构） | 整表操作 | **索引漂移问题**：并发结构/内容编辑会错位 | **结构操作整表软锁**（低频重操作）；MVP 可直接整表锁 |
| 流程图/导图 | 节点、连线 | 节点级 `flow:{id}:node:{nid}` | 拖不同节点都保留；同节点 LWW | 节点级锁；MVP 整元素锁 |
| 流程图 | 删节点级联删连线 | 同批 op | 连线端点不存在 → 一并删除 | 删除时同批发连线删除 op |
| 2D/3D | 变换（位置/尺寸/旋转） | `el:{id}:transform-{field}` | 字段级；与笔迹同模式（预览流+落定一条 op） | 尺寸调整对话框期间软锁 |
| 2D/3D | 内部参数/场景数据 | `el:{id}:payload` 整体 | 整体 LWW | 编辑期元素软锁 |

**表格索引漂移（务实解法）**：结构操作（增删行列）走整表软锁 + 整体 op；内容编辑走单元格级。进阶（M10.5 后）：行列引入稳定 UUID + 序列 CRDT（RGA/Logoot）彻底免锁——**第一期不做**。

**undo 与协同**：本地 undo = 发一条反向 op（恢复快照）而非本地回滚；远端 op 不入本端撤销栈；极端情况下 undo 覆盖远端新值按 LWW 处理（不追求"协同 undo 完美语义"，先保证一致）。

### 5.9 Presence 感知（光标 / 选区 / 页面 / 视口）

| 事件 | 载荷 | 频率/节流 | 可靠性 | 超时清理 |
|---|---|---|---|---|
| `presence:cursor` | `{userId, pageId, x, y}` | 50ms（20Hz） | volatile | 10s 未更新移除 |
| `presence:selection` | `{userId, elementIds[]}` | 变化即发（≥100ms 节流） | volatile | 同上 |
| `presence:page` | `{userId, pageId}` | 变化即发 | 可靠 | 同上 |
| `presence:viewport` | `{userId, pageId, offset, zoom}` | 200ms；仅**跟随模式**下上报 | volatile | 同上 |

- 「可丢」语义：桌面由应用层迟滞队列模拟；Web 用官方 volatile（见 §5.4 注）。
- 坐标一律为**画布世界坐标**（与既有 `drawing.points` 口径一致），缩放由各自视口换算。
- 远端光标渲染在 `lib/widgets/collab/remote_cursors.dart`，按 userId 哈希配色，500ms 缓动插值，静止 5s 淡出。
- 参与者临时掉线（心跳超时未断连）显示「重连中」灰态，不立即从参与者列表移除（防闪烁）。

**M3 落地注记**：`presence:page` / `presence:viewport` 独立事件名在 M3 仍未启用，经泛化 `presence:preview` 承载（`kind:'page'` / `kind:'viewport'`，服务端透传不解释，同 M2 口径）；页对齐按**页序后缀近似**——帧 `pageId` 与本地页 id 全等直接命中，否则按 `-page-<n>` 后缀取页序、页序相等即放行（跨端 pageId 命名空间不同）；页结构跨端尚未同步，M3 跟随功能同口径。

### 5.10 跟随与演示（互动模式核心）

| 流程 | 触发 | 数据流 | 退出 |
|---|---|---|---|
| 跟随 `followUser` | 参与者点击某人「跟随」/ 教师广播 | 被跟随者视口（`presence:viewport`）→ 跟随者本地强制同步视口+当前页；跟随者保留自己的光标/批注权 | `stopFollow` / 被跟随者离开（自动停） |
| 演示 `startPresent` | Host/CoHost 发起 | 服务端置房间模式 Present；Presenter 可写（Host/CoHost 恒可写），其余角色默认只读（已授权者除外）；新加入者默认跟随 Presenter | `stopPresent` 恢复房间原模式 |
| 举手 | Participant `interactive:raiseHand` | 广播到 Host 参与者面板；Host/CoHost `grantControl` 后该用户临时可写 | `lowerHand` / 收回控制 |
| 分组（M10.5 预留） | — | `board:<id>:group:<gid>` 子房间 + 组长视图 | — |
| 投票/计时（M10.5 预留） | — | 事件名已定（`interactive.vote.*` / `interactive.timer.*`），业务后置 | — |

模式切换为**服务端权威**：`interactive:modeChanged` 广播后，各客户端本地收窄/放开工具与权限（工具面板禁用态），引擎 `permission` 域同步更新本地判定缓存。

**M3 落地注记**：写权判定统一为 `effectiveCanWrite = grantedWrite || 角色 ∈ {Host, CoHost} || (present && 角色 = Presenter) || (free && 角色 ≥ Write)`——**2026-11 修订（free 默认放开）**：free（默认）模式下 ≥Write 角色（Host/CoHost/Presenter/Participant）默认可写、Viewer/Guest 仍只读，默认协作开箱可用；present 收窄不变（仅 Presenter 可写）。原 **2026-10「默认无权限」**语义（非管理角色含后加入者默认只读、free/present 一致）由本次修订取代；后加入未授权与「授权→收权」后完全等效（均回落角色默认写权）。`grantedWrite` 为会话态临时写权，经 `interactive:grantControl`/`revokeControl`（≥CoHost，目标不得为 Host/CoHost）置/清——**revoke 仅清 `grantedWrite`、不改变会话角色（与「从未授权」完全等效）**，单播 `interactive:roleChanged {userId, role, grantedWrite}` + 广播 `board:participants.updated` 同步；`board:ops` 与 `lock:acquire` 的写权校验统一走该判定。

### 5.11 权限校验（双层）

1. **服务端权威**：每个入站事件先过角色矩阵（§5.1）；非法直接回 ack/error（单播），不广播、记审计。token 校验复用 13 svc-api 的 JWT/角色。
2. **客户端本地**：进入房间时把角色映射进引擎 `permission` 域（本地缓存），UI 层据此禁用工具入口（不发无效请求）；远端权限变更（`interactive:roleChanged`）即时刷新。
3. 与 13 的边界：board 协作者/分享是**持久权限**（REST 层）；房间角色是**会话权限**（Socket 层），后者不得超过前者（服务端加载协作者表做上限裁剪）。

**M3 落地注记**：上限裁剪 seam 已落位——`clampSessionRole(tokenRole, requested)`（`services/realtime/src/types.ts`）；会话角色只由服务端经该 seam 显式产生（join 初始 / join 冲突降级 / host 移交），客户端消息不得改自身角色；v1 恒放行显式授权，待板级协作者表（13 svc-api）接入后按 `tokenRole` 上限裁剪（如持久 Viewer 禁授 Host）。

### 5.12 断线重连与离线队列

```text
网络断开（心跳超时 / WS 错误）
  → TransportState=Reconnecting（UI：同步状态 chip 转黄）
  → 本地操作继续：applyLocal 正常，sendOperation 全部入 pending 队列
  → 退避重连（1s→2s→4s→…→30s）
  → 重连成功 → 重新握手 → board:join {lastSeenVersion}
  → 服务端回差分 board:ops（自 lastSeenVersion 起）→ 引擎 applyRemote
  → flush pending（逐条按序，**先拉后推**：先收差分再推积压，少一次覆盖抖动）
  → 双方收敛 → 状态回 Connected；UI 显示「已重新同步」
```

- `lastSeenVersion` = 本地已知的**每 actor 最大 seq 向量**（即 `crdt.encodeState` 的版本语义）。
- 连续重连失败 5 次 → 降级进入「单机模式」：停止重连、隐藏在线协作 UI，但保留 pending 队列（用户可手动重连触发合并）。与全仓「优雅降级」哲学一致。

### 5.13 心跳与延迟监控

| 层级 | 机制 | 用途 |
|---|---|---|
| Engine.IO | 服务端 ping `2` / 客户端 pong `3`（25s/20s，由 OPEN 帧下发） | 连接存活判定 |
| 应用层 | `board:ping {clientTime}` → ack 回 `{serverTime}`，每 5s | RTT 测量 → UI 延迟指示（绿<100ms / 黄<300ms / 红≥300ms） |
| 时钟 | 首次连接校正 offset（NTP 式三样点可后置，《预留设计》§9.4 目标误差<50ms） | CRDT timestamp 跨端可比（回放对齐预留） |

### 5.14 退出、被移除与房主转移

- `board:leave`（主动）→ 释放自身锁 → 广播 `participants {left}` → 关闭连接。
- 被移除（Host 踢人）→ 服务端先发 `room:removed {reason}`（单播），再断开连接；客户端收后进入只读并提示。
- 房主离线 → 服务端默认立即将 Host 移交给最早加入的 CoHost（无则最早的 Write 角色），广播 `interactive:hostChanged`；防抖窗口可配（`WB_HOST_TRANSFER_MS` > 0 时启用，窗口内同 userId 回归取消移交）。
- 房主自举：房间无在线 Host 时，首个加入的可写角色（Host/CoHost/Presenter/Participant）自动升 Host（免 token 的房主体验；Viewer/Guest 只读声明不参与），审计 `interactive.hostBootstrapped`。
- 最后一人离开 → 房间数据保留 10min（防抖动重连），之后销毁；op 日志按 §7 快照策略处理。

**M3 落地注记**：踢人与房主转移已落地——踢人经 `interactive:removeUser`（≥CoHost 且级别须严格大于目标），先单播 `room:removed {code:'Removed', message:'Removed from the board', reason:'removed'}` 再断开连接，审计必落；Host 离场默认立即移交（`WB_HOST_TRANSFER_MS` 可配防抖窗口，开启时同 userId 回归取消），移交最早 CoHost（无则最早可写角色），广播 `interactive:hostChanged` + `participants.updated`、单播新 Host `roleChanged`；双 Host join 冲突降级 CoHost（审计必落）；房主自举：房间无在线 Host 时首个加入的可写角色升 Host（审计 `interactive.hostBootstrapped`；Viewer/Guest 只读声明除外）。

## 6. 消息契约（事件总表）

| 事件 | 方向 | 载荷 | 可靠性 | 节流 | 最低角色 |
|---|---|---|---|---|---|
| `board:join` | C→S | `{boardId, pageId?, lastSeenVersion?}` | 可靠 | — | Viewer |
| `board:joined` | S→C | `{participants, role, mode, locks, stateVector, presenterId?, snapshot?}` | 可靠 | — | — |
| `board:joinAck` | C→S | `{localSeqs}`（请求补差分） | 可靠 | — | Viewer |
| `board:ops` | 双向 | `[op…]`（op 结构同 crdt 域 `{actor,seq,key,value,timestamp,origin}`） | 可靠+ack | 100ms 攒批 | Write |
| `board:fetchOps` | C→S | `{actor, fromSeq}` | 可靠 | 按需 | Viewer |
| `board:leave` | C→S | `{}` | 可靠 | — | Viewer |
| `presence:cursor` | 双向 | `{userId, pageId, x, y}` | volatile | 50ms | Viewer |
| `presence:selection` | 双向 | `{userId, elementIds}` | volatile | 100ms | Viewer |
| `presence:page` | 双向 | `{userId, pageId}` | 可靠 | — | Viewer |
| `presence:viewport` | 双向 | `{userId, pageId, offset, zoom}` | volatile | 200ms（跟随态） | Viewer |
| `presence:preview` | 双向 | 泛化中间态（M2 起）：`{kind, pageId, …}`——ink：`{strokeId, points(增量), style}`；transform：`{elementId, x, y, w, h}`；cursor：`{x, y}`；selection：`{elementIds}`；服务端转发注入权威 `userId`（覆盖载荷同类字段） | volatile | 33ms（cursor 50ms） | Write |
| `lock:acquire` / `lock:release` / `lock:renew` | C→S | `{elementId}`；ack：acquire 授予 `{ok:true, granted:true, expiresAt}` / 占用 `{ok:true, granted:false, holderUserId}`、release `{ok:true}`、renew `{ok:true, expiresAt}` | 可靠+ack | — | Write |
| `lock:changed` | S→C | `{elementId, userId, action: acquired/released/expired, expiresAt?}`（`expiresAt` 仅 acquired） | 可靠 | — | — |
| `interactive:raiseHand` / `lowerHand` | C→S | `{}` | 可靠+ack | — | Viewer |
| `interactive:grantControl` / `revokeControl` | C→S | `{userId}` | 可靠+ack | — | CoHost |
| `interactive:startPresent` | C→S | `{}` | 可靠+ack | — | CoHost |
| `interactive:stopPresent` | C→S | `{}` | 可靠+ack | — | Presenter |
| `interactive:removeUser` | C→S | `{userId}`（级别须严格大于目标） | 可靠+ack | — | CoHost |
| `interactive:follow` | C→S / S→C | C→S：`{targetUserId}`；S→C（单播）：`{followerUserId}` | 可靠 | — | Viewer |
| `interactive:unfollow` | C→S / S→C | C→S：`{targetUserId}`；S→C（单播）：`{followerUserId}` | 可靠 | — | Viewer |
| `interactive:modeChanged` | S→C | `{mode, by, presenterId?}`（present 时带 presenterId） | 可靠 | — | — |
| `interactive:roleChanged` | S→C | `{userId, role, grantedWrite}` | 可靠 | — | — |
| `interactive:hostChanged` | S→C | `{newHostId}` | 可靠 | — | — |
| `board:participants` | S→C | `{joined?/left?/updated?}`（参与者条目含 `grantedWrite?` / `handRaised?`） | 可靠 | — | — |
| `board:ping` | C→S | `{clientTime}` | 可靠+ack | 5s | Viewer |
| `room:error` / `room:removed` | S→C | `{code, message, reason?}` | 可靠 | — | — |
| `board:checkpoint` | C→S | `{stateVector, payload}`（payload 为字符串，UTF-8 字节 ≤ 10MB） | 可靠+ack | — | CoHost |
| `board:checkpointRequest` | S→C | `{stateVector}`（单播） | 可靠 | — | — |

**传递模式说明**：默认房间广播（`to(room)`，排除发送者）；以下为**定向单播**：`board:joined`、ack/错误回执、`fetchOps` 补差分响应、`room:removed`、`lock` 拒绝回执、`interactive:roleChanged` 指向个人的通知。跨会话定向一律用 `user:<userId>` 房间（`socket.id` 重连会变）。

**M2 落地注记（T2a/T2b/T2f 实测口径）**：`presence:preview` 为泛化转发——服务端在房校验、排除发送者、透传载荷并注入权威 `userId`，无 ack、不落审计（防高频流审计膨胀）；光标/选区在 M2 经该泛化事件承载，独立 `presence:cursor`/`presence:selection` 事件名留 M3+ 启用；`lock:*` 的占用/拒绝经 ack 单播回执（不广播），`lock:changed` 仅 `acquired`/`released`/`expired` 广播（`renew` 不广播、不审计）；锁 TTL 30s、持有者 10s 心跳续约、断连/超时自动释放。

**M3 落地注记（T3.1/T3.3/T3.5 实测口径）**：`interactive:*` 与 `board:checkpoint` 的 ack 均为轻量形状 `{ok:true}` / `{ok:false, reason}`（reason：`not-in-room` / `forbidden` / `invalid-argument` / `user-not-in-room` / `invalid-target` / `not-presenting` / `payload-too-large`）；权限拒绝只回 ack、不广播，落审计 `authz.denied`。审计口径：管理操作（`startPresent` / `stopPresent` / `grantControl` / `revokeControl` / `removeUser` / host 移交与冲突降级）必落；`raiseHand` / `lowerHand` / `follow` / `unfollow` 不落（follow/unfollow 无 ack、目标不在房静默忽略）；普通 op 入账按 32:1 采样（`ops.sampled`）。checkpoint 参数默认值：触发阈值 500 op、请求超时 15s、payload 上限 10MB（`WB_CHECKPOINT_OP_THRESHOLD` / `WB_CHECKPOINT_TIMEOUT_MS` / `WB_CHECKPOINT_MAX_PAYLOAD_BYTES` 可配）。

错误码沿用既有风格：`Unauthorized`（44 CONNECT_ERROR）、`Forbidden`、`NotFound`、`Conflict`（锁冲突）、`VersionIncompatible`。

## 7. 服务端设计（services/realtime）

| 项 | 设计 |
|---|---|
| 技术栈 | Node.js + `express` + `socket.io`（v4.x，协议即 Socket.IO v5） |
| 端口 | 默认 `8790`（自选，避开 api 8080 / mcp 8788 / ai 8000 / convert 8001）（❓D5） |
| 命名空间 | `/board`；连接 auth：`{token, boardId, clientVersion}` |
| 房间态 | 参与者表 / 锁表 / 模式 / 版本水位 / op 环形日志（内存） |
| 单播用途 | `joined`、ack/错误回执、`fetchOps` 响应、`room:removed`、个人定向通知（§6 说明） |
| **快照策略（关键）** | **服务端不做 CRDT 合并**：①MVP 不裁剪，op 日志房间生命周期内全量保留，新成员回放；②长会话（水位超阈值）由**当前水位最高且角色 ≥ CoHost 的在线客户端**（其 C++ 引擎调 `encodeState`）上传 checkpoint，服务端**只存 blob 不解释**，新成员从 checkpoint + 其后增量开始 |
| 持久化 | ❓D4：MVP 内存；后续通过 13 svc-api 落 op 日志（或直连 Redis） |
| 审计 | 房间生命周期 + 权限拒绝 + 踢人/授权等管理操作必落；普通 op 采样（详见 D4） |
| 水平扩展 | `@socket.io/redis-adapter` 预留（多实例房间扇出）；MVP 单实例 |
| 测试 | vitest，离线自起服务器，风格对齐 services/mcp_server（tests/ 分层 + fake 传输） |

**M3 落地注记（checkpoint / T3.5）**：触发阈值 500 op（`WB_CHECKPOINT_OP_THRESHOLD` 可配，自上次 checkpoint 起累计入账 op）；候选口径为**近似实现**——原定「水位最高且角色 ≥ CoHost 的在线客户端」，服务端不跟踪每客户端水位，v1 以在房最早的 Host/CoHost 近似（偏差登记，待客户端上报递增水位后收窄）；inflight 去抖 + 15s 请求超时（超时仅清 inflight、不清计数，由后续 op 批按当前水位重触发）；服务端**只存不解释**（payload 原样字符串，不解析不合并）；v1 恢复范围**仅新成员**——join 未携带（或空）`lastSeenVersion` 且存在 checkpoint 时经 `board:joined.snapshot` 下发，已在房成员仍走增量 op；客户端恢复守卫：`decodeState` 为整状态替换，仅本地 crdt 文档不存在时执行（`encodeState` 探测 `NotFound` → `create` 复查 → 恢复并以 `snapshot.stateVector` 重置水位），本地已有文档一律跳过（由 join 后的增量 `board:ops` 覆盖）。

## 8. 与现有代码的接线

### 8.1 C++ 引擎（05-core-collab 主责）

| 现状 | 目标改动 |
|---|---|
| `sync.connect` 立即返回成功（占位） | 真实发起 sioxx 连接 + Socket.IO 握手；状态机 Inactive→Connecting→Connected/Reconnecting/Failed |
| `sync.sendOperation` 只计数/入队 | 在线 → 出站队列（100ms 攒批 + ack 重试 3s×3）；离线 → 保持 pending 语义 |
| `sync.sync` 清空队列（假） | 重连后：请求差分（`join{lastSeenVersion}`）→ 先拉后推冲刷 pending → 回执 `{synced, pendingCount}` |
| `sync.queue` | 语义不变（pending 查询） |
| `sync.capabilities` | `socketio` → `implemented=true`；Transport provider 转 true |
| `sync.status` | `transport: "socketio"`；新增 `latencyMs`、`participants`、`reconnectCount`（增量字段不破坏既有断言） |
| **新增 op：`sync.events`** | drain 语义：返回自上次调用后的入站事件（生效 op / 预览 / 房态变更 / 状态迁移），供 Dart 侧 50ms 轮询（§8.2） |
| **新增 op：`sync.sendPreview`** | 中间态可丢消息出站（volatile/迟滞队列），载荷 `{kind, …}` |
| `crdt` / `permission` / `audit` 域 | **不动**：合并、权限判定、审计复用既有实现 |

**并发与锁约定（必须遵守）**：sioxx 的 Boost.Asio I/O 线程（自建 `io_context` 线程）只做协议收发与队列搬运，**严禁网络线程直接 `invokeDomain`**；入站事件入队列、出站消息出队列；域调用一律发生在 FFI 调用线程（`events` drain / `sendOperation` 调用时）。不触碰「域处理持 `SceneStore::mutex`、持锁期间禁止 `invokeDomain`」的既有约定。

**SocketIOTransport 结构**（`core/src/sync/socketio_transport.{h,cpp}`）：实现 `reserved::Transport` 接口（connect/disconnect/getState/send/getType）；库 API 收敛在这一个文件（薄封装），换库不改调用方。

### 8.2 FFI 事件面：远端事件下发（D6 定稿）

桌面网络在 C++ 后，远端事件需要一条下发通道；且**接收侧合并发生在引擎内**（§5.4），Dart 只需要"生效结果"：

- **MVP（定稿）**：新增 `sync.events`（drain 语义）+ Dart 侧 50ms 定时轮询。返回结构分段：`{ops:[生效op…], previews:[…], room:{participants/locks/mode…}, status:{…}}`。**不新增回调通道类符号**；数据面新 op 经**薄转发 C 符号**暴露——sync 5 个（`wb_sync_join` / `wb_sync_send_operation` / `wb_sync_flush` / `wb_sync_events` / `wb_sync_send_preview`）+ crdt 2 个（`wb_crdt_create` / `wb_crdt_apply_local`），协同面符号 4→11（既有 4 符号签名不变）；50ms 延迟与 presence 节拍匹配，实现与测试最简。
  > 勘误（M1 实施，决策 D-A）：v1.0 原文"零新 C 符号（走既有域 op 路由）"与 FFI 现状（`wb.h` 仅 4 个 sync 符号、crdt 无 C 符号，Dart 无途径触达新 op）冲突；修正为"不新增回调通道类符号 + 数据面薄转发符号"，符号为纯增量。
- **后置（M5 可选）**：`wb_sync_set_event_callback` + `NativeCallable.listener` 快通道（跨线程回调复杂度高，按需再上）。
- **下发口径**：`crdt.applyRemote` 中 `ApplyRegister` 返回"生效"的 op 才进队列（LWW 败者不下发）——Dart 直接应用，无需自行比较 timestamp；极端不一致由重连对账（`encodeState`/快照）纠正。

## 9. 降级与容错（延续全仓「优雅降级」哲学）

| 故障 | 行为 |
|---|---|
| 服务端不可达 / 未配置 | 单机模式，协作 UI 隐藏，功能零阻塞 |
| 握手被拒（44） | 提示原因（token 过期→引导刷新；版本不符→提示升级）；本地继续编辑 |
| 房间不存在 / 已销毁 | 提示并回落单机；若本地有 pending 则保留 |
| 锁服务异常 | 软锁失效降级为「无锁 + CRDT 兜底」，不阻塞编辑 |
| op 乱序 / 重复 / 跳号 | CRDT 去重幂等 + `fetchOps` 补洞（§5.4） |
| 桌面端 sioxx 无 volatile | 应用层迟滞队列兜底（§5.4 注） |
| 主动切「离线」（既有 `setOffline`） | 断开连接但保留房间态；恢复后按 §5.12 收敛 |

## 13. 兼容性与风险

1. **第三方库成熟度（桌面）**：sioxx 0.3.0 较新、社区小，volatile / ack 自动重试 / 断线漏包恢复在 roadmap（本设计已由应用层兜底）。缓解：M0 POC 先验；`SocketIOTransport` 薄封装隔离（换库不改调用方）。
2. **Boost 引入成本**：sioxx 依赖 Boost.Asio/Beast（header-only 为主）。缓解：优先 FetchContent；wasm preset 不引入；若构建约束受限或 POC 不过，回退评估其他 EIO v4 客户端（接口不变）。
3. **Web 端画布能力分期**：WASM 核心仍为占位（演示画布），画布 op 同步（W2）依赖 WASM 就绪；W1 协作层不阻塞。
4. **快照/checkpoint 机制**：MVP 靠全量回放（房间寿命内 Op 量可控）；长会话 checkpoint 依赖"客户端上传 encodeState"，服务端只存不解释——M3+ 落地，期间巡检 op 日志水位。
5. **服务端新增语言面**：Node 已是既有栈（api/mcp），无新增语言；但 realtime 是新服务目录，需同步 17/18 号文档与 CI。
6. **既有契约稳定**：`sync` 域既有 op 只增不改；`status`/`capabilities` 的增量字段不得删改既有键（测试按现状断言）。
7. **跨端契约一致性**：桌面（C++/sioxx）与 Web（JS 客户端）实现不同，契约一致性靠 §6 事件表 + 服务端契约测试（vitest 逐事件断言）守住。
