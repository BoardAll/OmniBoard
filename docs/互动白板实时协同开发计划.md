# 互动白板实时协同开发计划

- 关联设计：`docs/互动白板实时协同设计文档.md`（v1.0 定稿）
- 日期：2026-09-29
- 组织方式：按里程碑拆任务，每个任务标注负责 Agent（项目 18 个模块专家 Agent 体系）；**每个里程碑末尾由 `wb-verify-agent` 做集成门验证**
- 原则：复用既有域（`crdt`/`permission`/`audit` 为复用、不动）；新增能力走既有扩展点（sync 域 op / 域路由），不新造平行链路

---

## 1. Agent 分工总览

| Agent | 本轮承担 |
|---|---|
| **wb-core-collab-agent** | 【主责】sync 域真实化、SocketIOTransport（sioxx）、出站/离线队列、`sync.events`/`sendPreview`、冲突语义（exists 规则 / key 粒度）落地 |
| wb-core-foundation-agent | sync 新增域 op 的契约评审（域路由 / UTF-8 JSON 信封）；`docs/modules/01`、`05` 文档同步 |
| wb-core-model-agent | `drawing` 类型进入 core 元素契约（笔迹落 CRDT 前置）；元素删除/批量语义配套 |
| wb-core-domain-agent | 专业元素（表格/流程图/导图/2D/3D）payload 的 op key 粒度评审（冲突矩阵落地核查） |
| wb-dart-core-agent | `core_dart` 的 sync 服务扩展（`events`/`sendPreview`/status 增量字段） |
| wb-app-desktop-agent | sync_service 接 FFI、画布出口/入口、笔迹两阶段、橡皮擦行为、collab UI |
| wb-app-web-agent | JS 客户端桥（js_interop）、realtime_service、W1 协作层、W2 画布 op（后置） |
| **wb-svc-api-agent** | 【主责】`services/realtime` 服务端（rooms/oplog/token/锁表/广播+单播/审计对接），复用其 JWT、中间件、测试模式 |
| wb-build-release-agent | sioxx + Boost 构建集成（FetchContent）、构建脚本 / CI 更新、打包验证 |
| wb-qa-testing-agent | 测试策略：ctest / vitest / flutter test 三层；§6 事件表逐条契约测试；回归基线 |
| **wb-verify-agent** | 每个里程碑集成门：全链路构建 + 全量测试 + 场景验收 |
| 不参与 | wb-core-ai / wb-core-render / wb-dart-client / wb-dart-ui（按需）/ wb-dart-platform（按需支持 Web js 桥）/ wb-svc-mcp / wb-svc-ai-gateway / wb-svc-convert |

> 说明：realtime 是新建服务目录（无专属 agent），由 **wb-svc-api-agent** 承接（Node/TS 专家，复用其认证/审计/幂等模式）；若 realtime 业务体量增长，可再派生 `wb-svc-realtime-agent`。
> wb-dart-ui-agent 按需：collab UI 若需新增 UI Kit 原子组件时介入。

## 4. 测试与验收要求

- **三层测试**：ctest（C++ sync/transport）/ vitest（realtime 契约）/ flutter test（桌面 + Web UI）
- **契约测试**：§6 事件表逐条 ≥1 个服务端契约测试，覆盖：权限拒绝 / 去重 / seq gap / 单播 vs 广播 / volatile 行为
- **e2e**：`tests/e2e` 新增"双端互见"场景（可复用 fixture 板）
- **基线纪律**：以"All tests passed + 记录日期"为准（测试数字会随并行开发漂移，不固化绝对值）

---

## 5. 风险与前置提醒

1. **sioxx POC 不过** → 回退评估其他 EIO v4 客户端（仅换 `socketio_transport` 实现，接口不变）
2. **Boost 构建成本** → T0.1 一并测量 CI 耗时；header-only 优先
3. **契约冻结层纪律**：sync 域既有 op 只增不改；任何"改既有键"都需 foundation 评审（测试按现状断言）
4. **Web 端行为差异**：直连 WS 与 polling 降级的时序差异需在 T0.2 记录，写入 12 号文档
5. **桌面画布双状态**：C++ crdt 为权威、Dart 画布为投影——T1.6 必须实现"生效 op 应用"口径（§8.2），避免 Dart 自行判定 LWW
