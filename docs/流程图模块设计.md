# 流程图模块设计

- 文档版本：v1.0
- 状态：详细设计稿
- 所属文档：《白板软件设计文档 v0.8》《齿轮圆盘交互详细设计 v1.1》《左侧栏与页面管理设计 v1.0》《可扩展工具栏设计 v1.0》
- 适用范围：Flutter UI + C++ 核心 + 云端 AI + MCP
- 定位：流程图是白板核心场景之一，支持标准流程图、泳道图、自动布局与手动微调

---

## 1. 设计目标

1. **标准流程图**：支持开始、处理、判断、输入输出等标准元素。
2. **快速创建**：拖拽连线自动创建节点，Tab / Enter 快速添加。
3. **自动布局**：一键整理，支持从上到下、从左到右。
4. **手动微调**：自动布局后可拖拽单个节点，连线自动跟随。
5. **泳道图**：作为流程图的一部分，支持横向/纵向泳道。
6. **连线智能**：自动避让、吸附锚点、支持折线/曲线。
7. **模板丰富**：内置多种流程图模板。
8. **AI 可调用**：所有流程图操作都有对应 Tool，AI 可生成、修改、整理。
9. **与工具栏集成**：选中流程图元素后显示专用上下文工具栏。

## 3. 数据模型

### 3.1 流程图元素

```cpp
enum class FlowchartNodeType {
  Start,          // 开始
  End,            // 结束
  Process,        // 处理
  Decision,       // 判断
  InputOutput,    // 输入/输出
  Document,       // 文档
  Database,       // 数据库
  ManualOperation,// 手动操作
  Connector,      // 连接点
  Annotation,     // 注释
  Swimlane,       // 泳道
  Custom          // 自定义
};

struct FlowchartNode {
  std::string id;
  FlowchartNodeType type;
  std::string text;
  Rect bounds;
  std::string styleId;
  std::string swimlaneId;
  std::vector<std::string> incoming;
  std::vector<std::string> outgoing;
  bool locked;
  bool hidden;
};

struct FlowchartConnector {
  std::string id;
  std::string fromNodeId;
  std::string toNodeId;
  std::string fromAnchor;
  std::string toAnchor;
  ConnectorStyle style;      // 直线 / 折线 / 曲线
  ArrowStyle arrowStart;
  ArrowStyle arrowEnd;
  std::string label;
  std::vector<Point> waypoints;
  bool autoRoute;
};

struct Swimlane {
  std::string id;
  std::string name;
  float position;
  float size;
  Orientation orientation;   // Horizontal / Vertical
  std::string color;
};

struct Flowchart {
  std::string id;
  std::vector<FlowchartNode> nodes;
  std::vector<FlowchartConnector> connectors;
  std::vector<Swimlane> swimlanes;
  LayoutDirection direction; // TopToBottom / LeftToRight
  std::string templateId;
};
```

### 3.3 图形库面板（折叠与更多图形）

- 左面板按固定顺序渲染「启用」的库：分组头部行为 [展开箭头][库名][图形数]，
  点击折叠 / 展开（key `wb-ctx-flow-lib-toggle-<libId>`）；折叠状态随偏好持久化。
- 图形项 key `wb-ctx-flow-shape-<typeId>`（既有口径不变）；拖拽 / 点击载荷统一为
  `WbFlowShapeSpec { type, component }`（组件项另带 `component` 数据）。
- 「我的组件」分组：组件项 key `wb-ctx-flow-component-<id>`（预览 + 名称 + 悬停删除
  key `wb-ctx-flow-component-remove-<id>`），组尾「导入组件」入口 key
  `wb-ctx-flow-component-import`。
- 「更多图形」按钮 key `wb-ctx-flow-more-shapes`（图形库末尾）打开对话框 key
  `wb-ctx-flow-more-shapes-dialog`：每个库一行复选（key
  `wb-ctx-flow-lib-check-<libId>`，默认全选）+ 图形数；切换即时生效并持久化。
- 偏好持久化经编辑器参数 `libraryStore`（窄接口 `WbFlowLibraryStore`）：桌面注入
  settings.json 适配器（`flowLibrary` 键），Web 注入 localStorage 适配器
  （`wb-flow-library` 键）；未注入时为内存实现（`WbFlowMemoryLibraryStore`）。

### 3.4 我的组件（导入 SVG / 图片）

- 导入源：编辑器参数 `componentImporter`（`Future<WbFlowComponentAsset?>`，返回
  name / mime / bytes）；未注入时导入入口隐藏。桌面经 Windows 文件对话框
  （`dialog.openComponent`，过滤 `svg / png / jpg / jpeg / webp / bmp / gif`）读字节；
  Web 经 `<input type="file">`（`accept=".svg,image/*"`）。
- 导入归一化：按扩展名 / 魔数判型；位图输入 ≤2MB、长边 >640 时等比重编码 PNG；
  SVG 源文本 ≤512KB、宽高经 viewBox 探测；组件总数 ≤30（超出拒绝）。
- 组件模型 `WbFlowComponent { id, name, mime, data(base64), width, height }`；渲染统一为
  `ui.Image`（SVG 经 flutter_svg 光栅化，缓存长边 ≤1024）；放置时长边 ≤160 等比
  （小图保留原尺寸）。
- 序列化：`.wbd` 节点 `component` 字段（mime / data / name / width / height），节点
  内嵌组件数据保证文件自包含；反序列化容错（非 Map / 缺 mime 或 data → null，
  回落虚线占位框）。
- 组件为应用级资源（跨白板共享），随库偏好持久化（桌面 settings.json
  `flowLibrary` 键 / Web localStorage `wb-flow-library` 键）。

## 4. 元素设计

### 4.1 开始 / 结束

- 形状：圆角矩形或椭圆
- 文本：默认“开始”/“结束”
- 颜色：绿色（开始）、红色（结束）
- 连接点：底部或右侧

### 4.2 处理

- 形状：矩形
- 文本：动作描述
- 颜色：蓝色
- 连接点：四边

### 4.3 判断

- 形状：菱形
- 文本：条件
- 颜色：橙色
- 分支：是 / 否，默认标签
- 连接点：四边

### 4.4 输入 / 输出

- 形状：平行四边形
- 文本：输入或输出内容
- 颜色：紫色
- 连接点：四边

### 4.5 文档

- 形状：波浪底矩形
- 文本：文档名称
- 颜色：灰色
- 连接点：四边

### 4.6 数据库

- 形状：圆柱
- 文本：数据库名称
- 颜色：青色
- 连接点：四边

### 4.7 手动操作

- 形状：梯形
- 文本：操作描述
- 颜色：黄色
- 连接点：四边

### 4.8 连接点

- 形状：圆
- 文本：编号或标签
- 颜色：灰色
- 用途：跨页连接

### 4.9 注释

- 形状：开放矩形
- 文本：说明
- 颜色：浅黄
- 连接：虚线到目标节点

## 7. 自动布局

### 7.1 布局方向

| 方向 | 说明 |
|---|---|
| 从上到下 | 默认，适合大多数流程 |
| 从左到右 | 适合横向流程 |
| 从下到上 | 可选 |
| 从右到左 | 可选 |

### 7.2 布局算法

- 基于分层布局（Sugiyama 风格）
- 步骤：
  1. 构建有向图
  2. 检测环
  3. 分层
  4. 减少交叉
  5. 分配坐标
  6. 路由连线
- 支持泳道约束
- 支持节点大小约束

### 7.3 自动布局参数

自动布局在无限坐标系中固定间距摆放（不再钳制进画布；轴向锚点取现有内容包围盒顶边与视口宽度中线）：

| 参数 | 默认 | 说明 |
|---|---|---|
| 同层间距 | 80px | 同层节点间距（minGapX） |
| 层间间距 | 60px | 层间距（minGapY） |
| 泳道条带 | 220px | 纵泳道列宽 / 横泳道行高 |
| 节点对齐 | 居中 | 左/中/右 |
| 连线风格 | 折线 | 直线/折线/曲线 |
| 避让距离 | 20px | 连线与节点距离 |

### 7.4 手动微调

- 自动布局后，可拖拽单个节点
- 拖拽时连线自动跟随
- 支持锁定节点位置
- 支持“重新布局”恢复自动结果
- 支持“部分布局”：只整理选中节点

### 7.5 自动布局工具 ID

| 操作 | 工具 ID |
|---|---|
| 自动布局 | flowchart.autoLayout |
| 部分布局 | flowchart.partialLayout |
| 重新布局 | flowchart.relayout |
| 锁定节点 | flowchart.lockNode |

类图三段式（类 `umlClass` / 接口 `umlInterface` / 多例类 `umlMultiton`）选中后在

### 10.7 无限画布交互

编辑器画布与黑板对齐：虚拟世界平面 ±5000 世界单位（场景 10000×10000，世界原点映射到场景中心），平移与缩放只改变相机；模型坐标为世界坐标（可为负），节点新增 / 拖动不再被钳制进视口，仅防呆钳制到虚拟平面。

| 操作 | 方式 |
|---|---|
| 平移画布 | 滚轮（Shift 横移）/ 空格 + 左键拖拽 / 中键拖拽 / 触控板双指 |
| 缩放画布 | Ctrl/⌘ + 滚轮（以指针为锚，`factor=exp(-dy/320)`，0.25×~3×） |
| 重置缩放 | 工具条「重置」（100%） |
| 适配内容 | 工具条「适配内容」/ 双击空白（内容包围盒 → 居中；scale 上限 1.0 不放大） |
| 框选 | 空白拖拽（相交即选；Shift 加选；单击空白清空选择） |
| 对齐参考线 | 拖动节点时 6 世界 px 阈值吸附（L/C/R × T/M/B），吸附显示虚线 |
| 端口连线 | 悬停 / 选中显示四边中点圆点：拖到目标节点建连线、拖到空白弹形状浮层快速建节点并连线 |
| 内联改字 | 双击节点（Enter / 失焦提交，Esc 取消） |

## 14. AI 调用

### 14.1 生成流程图

```text
“帮我画一个用户登录流程图”
→ flowchart.create

“生成一个订单审批流程，包含提交、审批、通过、驳回”
→ flowchart.create + flowchart.autoLayout

“把这段文字转成流程图”
→ flowchart.create + ai.parseText
```

### 14.2 修改流程图

```text
“在判断节点后面加上‘通知用户’”
→ flowchart.addNode + flowchart.connect

“把‘是’分支改成‘同意’”
→ flowchart.updateConnector + flowchart.setLabel

“把这个流程改成泳道图”
→ flowchart.toSwimlane

“自动整理这个流程图”
→ flowchart.autoLayout

“给判断节点加上是/否标签”
→ flowchart.labelBranches
```

### 14.3 分析流程图

```text
“找出这个流程图的死循环”
→ flowchart.analyze

“总结这个流程图的步骤”
→ flowchart.analyze + ai.summarize

“检查这个流程图有没有缺少结束节点”
→ flowchart.validate
```
